# ModeChat v0.5.0 产品需求文档（PRD）

> 版本：v0.5.0-draft｜作者：产品｜日期：2026-11-25
> 输入：`docs/parity-matrix.md`（136 项：✅73 / 🟡22 / ❌41）+ `docs/parity-arch-notes.md`（架构侧技术核实）
> 基准：DS Bot v0.3.6（源码 `D:\Mode Bot\DS-Bot` + 本机实机界面）
> 约束：Rust + GPUI 单二进制，**不引入 Node/TS 运行时**；UI 遵守 `docs/ui-design-spec.md`；数据可改结构但必须自带迁移

---

## 1. 背景

v0.4.0 已经完成“壳”的迁移：会话/群聊/目标派活/插话/旁路/隐私 bot/定时任务/微信企微 IM/MCP 连接器/浏览器与电脑操控工具/自更新/CI 都在（矩阵 ✅72 项）。对标 DS Bot 后，会被用户直接感知的问题集中在四类：

1. **承诺了但没闭环**（🟡22 里最刺眼的部分）：记忆只有团队和群、没有 Bot 自己的（A08/E03/E05/E09）；隐私 bot 只隔离了会话与搜索，**没隔离文件读写和其他 Bot 的外发**（D04/D05）；Chief 能派活但不能直接给别的 Bot 发消息（B05）。
2. **配置不透明**：模型窗口写死 128k/16k（P04），引擎的自动压缩其实在跑（`crates/rpi-harness/src/types.rs:327`（pi-rust checkout））但界面完全无感知（F06）；记忆注入预算写死 4000 字符（`src/data.rs:392/409`），大模型用不满。
3. **“有入口没功能”**：插件页（K09）、能力页（K07/K08）、飞书钉钉（J03/J04）三个页面点进去是空的或假的。
4. **规范没落地**：`ui_kit` 令牌齐全，但 145 处裸 `cursor_pointer`、175 处裸 `rounded(px())`、86 处裸字号、27 处硬编码 `rgb(`（Q02）。

v0.5.0 的目标不是“再抄一个 DS Bot”，而是**把已承诺的能力补齐到可用，把差异项要么接上、要么明确降级**。

## 2. 目标用户

| 用户 | 场景 | 本次要解决 |
| --- | --- | --- |
| **个人知识工作者**（主） | 一个窗口跟几个 Bot 长期协作，Bot 记得住偏好 | 记忆闭环、窗口可配 |
| **小团队负责人**（次） | 让 Chief 把活派给多人、跨群 | Team 工具闭环、群公告、阶段验收 |
| **处理私密资料的用户** | 私密项目只给一个 Bot 看 | 隐私 bot 的文件与出站隔离 |
| **多 IM 用户** | 在飞书/钉钉里对话 | 明确取舍（见 §8 待决） |
| **所有用户** | 点界面 | 令牌落地、零“点了没反应” |

## 3. 核心用户故事

- 作为长期用户，**我希望 Bot 记住我随口说过的偏好并在下次自动应用**，不用每次重复。（E03/E05/A08/E09）
- 作为团队负责人，**我希望 Chief 能直接给另一个 Bot 或另一个群发消息**，我只跟一个 Bot 说话。（B05/C13）
- 作为做长任务的用户，**我希望看到“正在压缩上下文”、能手动触发、能配置模型窗口**，而不是它悄悄改了行为。（F06/P04）
- 作为处理私密资料的用户，**我希望隐私 bot 读不到别的 Bot 的目录，删掉之后文件仍受保护**。（D04/D05）
- 作为审阅者，**我希望每个按钮长得一样、按下去有反馈**。（Q02）
- 作为配置定时任务的用户，**我希望选“每天 9 点”而不是自己写 cron**。（N06）

## 5. 验收标准（逐条可执行）

> 通用门禁：`cargo test --locked` + `cargo clippy --all-targets --locked -- -D warnings` 全绿。每条 P0 还需**真人操作**：后台启动 `ModeChat.exe` 点界面 + 截图。

### P0-1 Bot 记忆闭环
- **AC1**：对 Bot 说“记住：我习惯用中文回答”，**同一会话内** Bot 调 `remember` 成功；**新建会话后**首轮回复即体现该偏好。
- **AC2**：`remember` / `forget` / `recall` 三个工具各跑通一次：新增一条、删除一条、按关键词命中一条（返回条目原文）。
- **AC3**：Bot 详情页出现“记忆”行，显示条目数；点开面板能看到条目、能编辑与删除，改完下一轮生效。
- **AC4**：注入长度随模型窗口变化：把模型换成 32k 窗口，注入字符上限随之下降（不是固定 4000）。
- **AC5**：条目超上限时最旧条目自动进 `earlier` 主题，工具调用不报错。

### P0-2 上下文可见与可配
- **AC1**：构造长会话越过阈值时，聊天里出现**可见提示**（“正在压缩上下文”或类似），压缩完成后提示消失。
- **AC2**：命令面板/详情栏有“立即压缩”入口，点击后触发一次压缩且不新开会话。
- **AC3**：压缩后用户仍看到一段连续对话，不出现“新会话”分隔。
- **AC4**：`grep '128_000' src/*.rs` 结果为 0（写死窗口消失）。

### P0-3 模型配置
- **AC1**：设置 → 模型 → 某服务商下的每个模型可填 `contextWindow` 与 `maxTokens`；保存后重启仍在。
- **AC2**：不填时 UI 显示“默认”，行为按适配器默认（不崩、不报错）。
- **AC3**：填非法值（0、负数、非数字）时拒绝保存并给错误文案。

### P0-4 团队协作工具
- **AC1**：Bot A 调 `list_bots` 返回全体 Bot；隐私 bot 只显示名字 + “私有”，不显示目录/模型/正在做什么。
- **AC2**：Bot A 调 `message_bot(to=B, message=…)`，B 在自己会话里收到并回复，A 拿到回复。
- **AC3**：Bot A 调 `post_to_group(group=G, …)`，消息出现在群 G 记录里，成员按既有策略响应。
- **AC4**：隐私 bot 不能被 `message_bot` 读到内容（返回明确拒绝，不是静默失败）。

### P0-5 隐私 bot 补完
- **AC1**：隐私 bot 的 `read`/`write` 访问工作目录之外路径时，**先出审批卡**；拒绝后工具返回失败。
- **AC2**：删除隐私 bot 后，其目录仍在且被登记；其他 Bot 的 `list_bots`、全局搜索、群成员列表都看不到它。
- **AC3**：设置页有“保留的隐私 bot 目录”，可列出手动解除保护。

### P0-6 UI 债清零
- **AC1**：`grep -c '\.cursor_pointer()' src/*.rs` → 仅允许出现在 `ui_kit.rs`。
- **AC2**：`grep -c '\.rounded(px(' src/*.rs` → 0（动态值走白名单 + 注释）。
- **AC3**：`grep -c 'text_size(px(' src/*.rs` → 仅 `ui_kit.rs` 令牌定义。
- **AC4**：`grep -c 'rgb(' src/*.rs` → 0。
- **AC5**：`scripts/ui-lint.ps1` 可一条命令跑完上述四条，CI 里跑，非绿即失败。

### P0-7 有入口没功能收口
- **AC1**：逐页点完 17 个设置页 + 主界面全部可点元素，每个控件都有可见响应（状态变化 / toast / 空态说明），**零“点了没反应”**，过程截图留档。
- **AC2**：插件页、飞书、钉钉若不做，显示明确空态（例：“当前版本不支持飞书通道，计划 v0.6.0”），且文案进 `i18n.rs` 中英两套。
- **AC3**：能力页不再是 4 行只读硬编码——要么能开关，要么明确写“只读”。

### P1 通用验收
每条 P1 需：功能可用（真人操作截图）+ 对应单元测试 + `docs/parity-matrix.md` 状态从 🟡/❌ 改 ✅ 并标版本。

## 6. 非目标（本次明确不做）

1. 不引入 Node / TypeScript / Electron 运行时。
2. 不做 Office（P2-1）——最大差异块，需独立排期。
3. 不做内嵌浏览器面板（P2-3），继续“系统浏览器 + 工具控制”。
4. 不做 QQ/Telegram/Discord/Slack（P2-10），`crates/bots-service/src/lib.rs:59` 已标下线，本次维持。
5. 不做插件宿主与技能体系（P2-11）。
6. 不做多语言扩展（P2-8），维持中英双语。
7. 允许改数据格式，但必须自带迁移，`~/.mode-bot` 旧数据不丢（`goal.json` 加字段即属此类）。
