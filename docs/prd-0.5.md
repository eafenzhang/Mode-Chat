# ModeChat v0.5.1 产品需求文档（PRD，含 v0.5.0 基线）

> 版本：v0.5.1｜作者：产品｜日期：2026-11-25
> 输入：`docs/parity-matrix.md`（136 项：v0.5.1 口径 ✅89 / 🟡20 / ❌27）+ `docs/parity-arch-notes.md`（架构侧技术核实）
> 基准：DS Bot v0.3.6（源码 `D:\Mode Bot\DS-Bot` + 本机实机界面）
> 约束：Rust + GPUI 单二进制，**不引入 Node/TS 运行时**；UI 遵守 `docs/ui-design-spec.md`；数据可改结构但必须自带迁移
> 说明：正文的分期目标是 v0.5.0 立项时写的，v0.5.1 只做缺陷修复与复验，不新增功能范围；差异见 §9 变更记录。

## 1. 背景

v0.4.0 已经完成“壳”的迁移：会话/群聊/目标派活/插话/旁路/隐私 bot/定时任务/微信企微 IM/MCP 连接器/浏览器与电脑操控工具/自更新/CI 都在（矩阵 ✅72 项）。对标 DS Bot 后，会被用户直接感知的问题集中在四类：

1. **承诺了但没闭环**（🟡22 里最刺眼的部分）：记忆只有团队和群、没有 Bot 自己的（A08/E03/E05/E09）；隐私 bot 只隔离了会话与搜索，**没隔离文件读写和其他 Bot 的外发**（D04/D05）；Chief 能派活但不能直接给别的 Bot 发消息（B05）。
2. **配置不透明**：模型窗口写死 128k/16k（P04），引擎的自动压缩其实在跑（`crates/rpi-harness/src/types.rs:327`（pi-rust checkout））但界面完全无感知（F06）；记忆注入预算写死 4000 字符（`src/data.rs:392/409`），大模型用不满。
3. **“有入口没功能”**：插件页（K09）、能力页（K07/K08）、飞书钉钉（J03/J04）三个页面点进去是空的或假的。
4. **规范没落地**：`ui_kit` 令牌齐全，但 v0.5.0 立项时实测 145 处裸 `cursor_pointer`、175 处裸 `rounded(px())`、86 处裸字号、27 处硬编码 `rgb(`（Q02，为 v0.5.0 起点数字；v0.5.1 已清零，判据见 `docs/ui-design-spec.md` §11.1）。

v0.5.0 的目标不是“再抄一个 DS Bot”，而是**把已承诺的能力补齐到可用，把差异项要么接上、要么明确降级**。

## 2. 目标用户

| 用户 | 场景 | 本次要解决 |
| --- | --- | --- |
| **个人知识工作者**（主） | 一个窗口跟几个 Bot 长期协作，Bot 记得住偏好 | 记忆闭环、窗口可配 |
| **小团队负责人**（次） | 让 Chief 把活派给多人、跨群 | Team 工具闭环、群公告、阶段验收 |
| **处理私密资料的用户** | 私密项目只给一个 Bot 看 | 隐私 bot 的文件与出站隔离 |
| **多 IM 用户** | 在飞书/钉钉里对话 | 明确取舍（见 §8 待决） |
| **所有用户** | 点界面 | 令牌落地、零“点了没反应” |

## 3. 核心用户故事

- 作为长期用户，**我希望 Bot 记住我随口说过的偏好并在下次自动应用**，不用每次重复。（E03/E05/A08/E09）
- 作为团队负责人，**我希望 Chief 能直接给另一个 Bot 或另一个群发消息**，我只跟一个 Bot 说话。（B05/C13）
- 作为做长任务的用户，**我希望看到“正在压缩上下文”、能手动触发、能配置模型窗口**，而不是它悄悄改了行为。（F06/P04）
- 作为处理私密资料的用户，**我希望隐私 bot 读不到别的 Bot 的目录，删掉之后文件仍受保护**。（D04/D05）
- 作为审阅者，**我希望每个按钮长得一样、按下去有反馈**。（Q02）
- 作为配置定时任务的用户，**我希望选“每天 9 点”而不是自己写 cron**。（N06）

## 5. 验收标准（逐条可执行）

> 通用门禁：`cargo test --locked` + `cargo clippy --all-targets --locked -- -D warnings` 全绿。每条 P0 还需**真人操作**：后台启动 `ModeChat.exe` 点界面 + 截图。

### P0-1 Bot 记忆闭环
- **AC1**：对 Bot 说“记住：我习惯用中文回答”，**同一会话内** Bot 调 `remember` 成功；**新建会话后**首轮回复即体现该偏好。
- **AC2**：`remember` / `forget` / `recall` 三个工具各跑通一次：新增一条、删除一条、按关键词命中一条（返回条目原文）。
- **AC3**：Bot 详情页出现“记忆”行，显示条目数；点开面板能看到条目、能编辑与删除，改完下一轮生效。
- **AC4**：注入长度随模型窗口变化：把模型换成 32k 窗口，注入字符上限随之下降（不是固定 4000）。
- **AC5**：条目超上限（`INDEX_MAX_LINES = 80`，`crates/bots-service/src/memory_store.rs:25`）时最旧条目自动溢出到 **`topics/<kind>.md`**（`crates/bots-service/src/memory_store.rs:27` `TOPIC_DIR`、`:551` `write_topics`），工具调用不报错、条目文件一个不丢。
  > 口径更正（2026-11-25，据测试实测）：原文档写「进 `earlier` 主题」是错的，代码里目录名是 `topics/`，按 `kind` 分文件（user / feedback / project / reference）。功能一致，命名以代码为准。

### P0-2 上下文可见与可配

> **状态更正（2026-11-25，据测试 0.5.1 补测实测）**：
> 压缩本身、`chat.compacting` 状态、`compaction_status_row()`（`src/main.rs`）与命令面板里的「立即压缩」都已实现，但**v0.5.0 只接进了 classic 外壳**。默认外壳是 `wecom_mode`（取 `BOT_PILOT_CLASSIC_UI != "1"`），走 `wecom_transcript()` 和 `wecom_composer()`，v0.5.0 时这两处都没有接线：
> - 压缩状态行：v0.5.0 全文只有 main.rs 的 19411 / 19694 两处调用（v0.5.0 tag 版本行号，非当前 HEAD；当前 HEAD 对应 `:19403` / `:19686`），均在 classic transcript 内；`wecom_transcript` 区间内 0 命中。
> - 命令面板入口：`composer-plus`（v0.5.0 为 main.rs 的 20343，v0.5.0 tag 行号，非当前 HEAD）只在 classic composer；`wecom_composer` 的工具栏 id 仅 `wechat-tool-permission/folder/scissors/mic` + `wechat-send`，无 plus。
>
> 所以 P0-2 的 AC1/AC2 在 **v0.5.0 默认外壳下不成立**；**v0.5.1 已由 Q-01/Q-02 修复**：默认壳压缩行走 `WecomRow::Compacting` 分支、`composer-plus` 按钮 + `on_palette_shortcut` 两处派发。AC 仍按「默认外壳 + classic」双份判据保留，供复验。

- **AC1（默认外壳）**：默认形态下构造一次越过阈值的回合，聊天区出现压缩状态行（`id="chat-compaction-status"`），压缩结束后消失；全程至少一帧可见。
- **AC1b（classic 外壳）**：`BOT_PILOT_CLASSIC_UI=1` 下同一场景表现一致——两个外壳都必须有，不允许只有一边。
- **AC2（默认外壳）**：默认形态下从输入框「+」能打开命令面板，面板内含「立即压缩」并点击生效（触发一次压缩，不新开会话）。
- **AC2b（classic 外壳）**：`BOT_PILOT_CLASSIC_UI=1` 下同样成立。
- **AC3**：压缩后用户仍看到一段连续对话，不出现“新会话”分隔。
- **AC4**：`grep '128_000' src/*.rs` 结果为 0（写死窗口消失）。

> 验收口径：**以默认外壳为主判据**（用户默认看到的就是它）。classic 作为回归项，任一外壳缺失都算不通过——这正是 v0.5.0 漏掉的地方。

#### P0-2c 验收标准（Q-04 / Q-05，2026-11-25 追加）

> 与 P0-2 同一判据：**默认外壳为主，classic 为回归**。验收时**不设** `BOT_PILOT_CLASSIC_UI`。

- **AC5（Q-04 动作条出现）**：默认外壳下鼠标悬停任一消息气泡，动作条出现；用户气泡挂右上、助手气泡挂左上，不遮挡正文。
- **AC6（Q-04 复制生效）**：点「复制」，系统剪贴板内容与消息正文**逐字相等**（含换行）；点「复制代码」时剪贴板等于围栏内代码。
- **AC7（Q-05 新会话入口）**：**默认外壳三条**都能开新会话——① Ctrl+N（`:6840` `on_new_session_shortcut` → `:6847` 直通 `new_session_for_selected`）；② 标题栏「+」（`:27686` `wechat-new-session` → `:27695` 调同一函数）；③ **命令面板「新会话」**（`:7435` `PaletteCmd::NewSession` → `:7567` 派发；默认壳先点 `composer-plus`（`:28692`）开面板再选它）。三条都落盘（`sessions.save()`），重启后新会话仍在。
  > **Ctrl+N 的复验口径（2026-11-25）**：GPUI 下修饰键注入不可靠（`PostMessage` 只送进 `n`，与 v0.5.0 的 Ctrl+P 同一现象），故 Ctrl+N 记为「入口已实现、按键未注入实测」，不算通过也不算不通过。弱证据：起实例时带 `BOT_PILOT_DEBUG=1`，按键到达处理函数会向 stderr 打 `[action] NewSessionShortcut`（`debug_action` `:20828`，调用点 `:6846`）。有这行即证明链路通到 `:6847` → `new_session_for_selected`（`:6854`）。默认壳的新会话能力本身已由标题栏「+」和命令面板两条路径实测走通，不因这条未实测而阻塞。
  > **第四条（仅 classic）**：右栏 `detail-new-session`（`:20539`）位于 `fn right_panel`（`:20493`），只有 `classic_shell`（`:25956`）调用 `right_panel`；默认壳走 `chat_info_panel`（`:25992`），里面没有这个按钮。**故它不作为默认壳的判据，只在 `BOT_PILOT_CLASSIC_UI=1` 下验。**
  > **口径更正（2026-11-25，据源码复核）**：原写法「三者共用 `new_session_for_selected`」对命令面板不成立——`:7567` 是一份**行为等价但独立**的实现（自带 streaming 守卫、`push_history`、`sessions.save()`），未调用 `new_session_for_selected`。功能上三条都能用，但代码是两份，存在漂移风险，去重记 v0.6（与 R6 同源）。
- **AC8（明确不做）**：默认外壳**不做「引用」**——引用需写回 composer 的引用条，`wecom_composer` 无该 UI，属交互层改动，转 v0.6（矩阵 F10 记 🟡）。

### P0-3 模型配置
- **AC1**：设置 → 模型 → 某服务商下的每个模型可填 `contextWindow` 与 `maxTokens`；保存后重启仍在。
- **AC2**：不填时 UI 显示“默认”，行为按适配器默认（不崩、不报错）。
- **AC3**：填非法值（0、负数、非数字）时拒绝保存并给错误文案。

### P0-4 团队协作工具
- **AC1**：Bot A 调 `list_bots` 返回全体 Bot；隐私 bot 只显示名字 + “私有”，不显示目录/模型/正在做什么。
- **AC2**：Bot A 调 `message_bot(to=B, message=…)`，B 在自己会话里收到并回复，A 拿到回复。
- **AC3**：Bot A 调 `post_to_group(group=G, …)`，消息出现在群 G 记录里，成员按既有策略响应。
- **AC4**：隐私 bot 不能被 `message_bot` 读到内容（返回明确拒绝，不是静默失败）。

### P0-5 隐私 bot 补完
- **AC1**：隐私 bot 的 `read`/`write` 访问工作目录之外路径时，**先出审批卡**；拒绝后工具返回失败。
- **AC2**：删除隐私 bot 后，其目录仍在且被登记；其他 Bot 的 `list_bots`、全局搜索、群成员列表都看不到它。
- **AC3**：设置页有“保留的隐私 bot 目录”，可列出手动解除保护。

### P0-6 UI 债清零
- **AC1**：`.cursor_pointer()` 只允许出现在 `src/ui_kit.rs`（`Clickable::pointer()` 是唯一入口）。以 `ui-lint -Enforce` 第 1 条为准；实测 `ui_kit.rs` 9 处、`ui_kit.rs` 外 **0** 处。
- **AC2**：**数字字面量** `rounded(px(<N>))` 只允许出现在 `src/ui_kit.rs`、`src/theme.rs`；参数是令牌（`theme::RADIUS_*`）或算式（`size * 0.24` 头像等比）不算违规。`grep -c '\.rounded(px('` 会数出全部 188 处（大多是合规的令牌/算式），不能作判据；以 `ui-lint -Enforce` 第 2 条为准，实测字面量在允许文件外 **0** 处。
- **AC3**：**非令牌字号字面量 = 0**（判定口径见 `docs/ui-design-spec.md` §11.1）。`grep -c 'text_size(px('` 只数出 332 处、不区分合规与违规，不能作判据；用 `scripts/ui-lint.ps1 -Enforce` 第 3 条规则，实测非令牌字面量 0。
- **AC4**：`rgb(...)` 只允许出现在主题与图标着色白名单（`theme.rs`/`wechat_theme.rs`/`agent_icons.rs`/`avatar.rs`/`bot_icon.rs`/`brand_icons.rs`）；`grep -c 'rgb('` 会数出全部 22 处（都是白名单里的定义与图标着色），不能作判据；以 `ui-lint -Enforce` 第 4 条为准，实测白名单外 **0** 处。
- **AC5**：`scripts/ui-lint.ps1` 可一条命令跑完上述四条，CI 里跑，非绿即失败。
