## 0. 结论

默认形态是**微信风外壳**：`main.rs:3824 wecom_mode = BOT_PILOT_CLASSIC_UI != "1"`（默认 `true`），
`shell()`（`:25820`）据此分支到 `wecom_shell()`（`:25864`）；另一套 `classic_shell()`（`:25828`）
只有显式 `BOT_PILOT_CLASSIC_UI=1` 才走。

两套外壳是**各自手写的独立渲染代码**，不是同一组件换皮。已确认非等价能力 **14 项**，分三个方向：

| 方向 | 数量 | 谁受害 | 性质 |
|---|---|---|---|
| A. classic 有、默认壳没有 | 5 | **默认用户**（绝大多数人） | 缺陷 |
| B. 默认壳有、classic 没有 | 6 | 只有设了 `BOT_PILOT_CLASSIC_UI=1` 的人 | 基本可接受 |
| C. 双向残缺 | 3 | 都受害 | 缺陷 |

Q-01 / Q-02 只是 A 方向的第 1、2 项。A 方向还有 3 项同类问题，其中
**「默认壳无法复制消息」**和**「默认壳无新会话入口」**是日常高频动作，建议提前到 v0.5.2，不必等 v0.6。

## 1. 查法（可复现）

按**归属函数**统计，不按行号区间拍脑袋。

```
1) 抓所有 fn 起始行（含 0 缩进的自由函数），得到 [start, next_start-1] 区间
2) 待查符号全文扫行，落在哪个函数区间就算该函数引用它
3) 只比 chat 区域两组函数：
   classic 组：chat_header(19227-19317) / transcript(19325-19751) /
              composer(20160-20476) / right_panel(20477-20838)
   wecom   组：wecom_chat(27490-27612) / wecom_transcript(27614-27978) /
              wecom_composer(28468-28709) / chat_info_panel(26872-27438)
              加上只属 wecom 的四个辅助：wecom_working_row(27979-28085) /
              turn_footer(28086-28246) / chat_find_bar(28247-28339) / queue_panel(28340-28467)
```

**本轮踩到的两个测量陷阱，写下来避免下次再错：**

1. **子串陷阱**：`message_row` 是 `wecom_message_rows` 的子串。用 `Contains('message_row')` 扫，
   `wecom_transcript` 会冒出 8 处命中，看起来像默认壳也用 `message_row`。
   实际用 `message_row(` 精确匹配：调用点只有 `19460`、`19735` 两处，**都在 `transcript`（classic）**。
2. **归属陷阱**：`composer-retry` 出现在 `error_bar`（`:20092-20159`，`:20126`），
   `error_bar` 是**两壳共用**的方法（调用点 `20300` / `28526`），所以重试按钮两壳都有，不能算差异。
   同理 `attachment_chips` / `mention_panel` / `error_bar` 三个都是共用，已排除在差异之外。

| # | 问题 | 证据 | 影响 |

**同源风险高，列为待实测**，不要当成已验证结论引用。

## 6. v0.6 排序建议

| 顺序 | 项 | 理由 |
|---|---|---|
| **先做（或提前到 v0.5.2）** | A3 / A4 消息复制与引用、C1 新会话入口 | 日常高频动作缺失，用户会立刻骂；C1 还叠加 GPUI 键注入限制 |
| 次做 | A5 空态欢迎区 | 首次体验；成本极低，`transcript:19524-19633` 那一段可直接抽成共享函数 |
| 次做 | B3 队列可见性、B4 工作行、B1 回合 footer | 只影响 classic 老用户，但 B3「排队了看不见」会让人以为消息丢了 |
| 后做 | B2 死路修复、B5 / B6 / C2 / C3 | 边缘场景 |
| **架构建议** | 把 chat 区域抽成共享 render helper，两壳只做布局外壳 | 14 项差异的**共同根因**就是 `classic_shell` / `wecom_shell` 两套平行手写渲染。不解决这个，v0.6 之后还会继续漏（产品已记为风险 R6） |
