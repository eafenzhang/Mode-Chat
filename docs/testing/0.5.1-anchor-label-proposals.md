## 一、我实测出来的一个关键点：全小写函数名必须写成 `模块::函数`

门禁的判据会**否掉 Rust 里最常见的小写函数名**。我拿 `src/privacy.rs:201`（`pub fn precheck(`）做了对照实验：

```
原标签   （precheck：路径归属最长前缀判定）        → strict=125  skipped=95   ← 不变，被跳过
改标签   （`precheck` 路径归属最长前缀判定）        → strict=125  skipped=95   ← 加反引号也没用
改标签   （`privacy::precheck` 路径归属…）          → strict=126  skipped=94   ← 过了
```

原因在 `verify-parity-anchors.ps1:224`：`if ($w -notmatch '_' -and $w -notmatch '::' -and $w -cnotmatch '[A-Z]') { continue }`。`precheck` 全小写、无下划线、无 `::`，直接被丢弃；加上 `::` 前缀就满足条件，而 `:233` 的 `$tail = ($w -split '::')[-1]` 只拿最后一段去比对，所以 `privacy::precheck` 依然能在 ±12 行内精确命中。

**这条不用改脚本就能用：把全小写函数名一律写成 `模块::函数`。** 下面第二节标 `::` 前缀的那几条就是这个原因。

## 六、给门禁的建议（脚本归架构，这里只是实测结论）

现在「含 `_` / `::` / 大写」的判据是为了避开 `the`、`and` 这类英文虚词，但它同时把 **Rust 里最常见的小写函数名全部排除**。两条可选：

1. **不改脚本**：文档侧按第三节把全小写函数写成 `模块::函数`。已实测有效，代价是写起来啰嗦一点。
2. **改脚本**：标签里带反引号的标识符，只要能在该行 ±12 内精确命中就放行，不再要求含 `_`/`::`/大写——反引号已经表明这是符号，不需要再用命名风格猜。

我倾向 1，因为不动门禁逻辑，风险最小；2 更干净但需要架构改脚本并重跑全部负向用例。
