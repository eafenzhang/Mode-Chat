### D-09【中】群会话里隐私守卫把「自己的目录」判成越界，每次读文件都弹卡

**复现步骤**
1. 隔离数据根，群 `accept-group` 的成员是 Bot 12（目录 `C:\Users\Administrator\mode-bot-ws`）与 Bot 13（同目录）
2. 打开该群，让 Bot 12 读**自己工作目录**里的文件：`use read on C:\Users\Administrator\mode-bot-ws\OWN-READ-PROBE.md`

**期望**：自己目录直接放行，不弹卡（私聊里就是这样的，见下方对照）。

**实际**：弹出隐私越界卡，且归属写成调用者自己 —— `85` 那张的兄弟画面：

```
需要你的确认                            来自 12   风险 写入
工具 · read
越界访问：read 试图访问 C:\Users\Administrator\mode-bot-ws\OWN-READ-PROBE.md，归属 12
```

即「Bot 12 越界访问 Bot 12 的目录」。截图 `88-d09-group-own-dir-false-positive.png`。

**对照（同一份构建、同一 Bot、同一个目录）**：
- 私聊里让 Bot 12 读 `C:\Users\Administrator\mode-bot-ws\AGENTS.md` → **不弹隐私卡**，直接执行（`rv-51`、`rv-52`，之后那个 bash 卡是普通工具审批，不是隐私卡）
- 群会话里读同目录 → 必弹隐私卡

**根因**：`rpi_engine.rs:224 bot_id_from_identity()` 只认 `mode-bot:teammate:<id>` 前缀：

```rust
pub fn bot_id_from_identity(identity: &str) -> Option<String> {
    identity.strip_prefix("mode-bot:teammate:")…
}
```

而群成员会话的 identity 是 `mode-bot:group:<gid>:member:<botId>`（`crates/bot-team/src/group.rs:146 group_member_workspace_identity`），前缀对不上 → `bot_id = None` → `privacy::precheck(tool, args, None)` 拿不到 `caller_bot_id` → 自身目录豁免（`privacy.rs:230-232` 的 `own_tag` 判断）整段跳过 → 只要能匹配到任何已知目录就返回 `Some(owner)`。群里所有成员目录相同的场景下，读自己文件必然命中。

### D-10【低】隐私越界卡的风险等级恒为「写入」，与工具不符

同一分支 `rpi_engine.rs:455-460` 只把 `bash`/`powershell` 判成 `exec`，**其余一律 `write`**：

```rust
let risk = if matches!(lowered.as_str(), "bash" | "powershell") {
    "exec"
} else {
    "write"          // read / edit / write / mcp__* 全归到这里
};
```

而常规审批路径（`rpi_engine.rs:491-518`）是三档：`bash/powershell/computer_*/browser_*` → `exec`；`write/edit/automation_*/团队工具/mcp__*` → `write`；**其余 → `read`**。两条路径口径不一致。

结果：`read` 的越界卡显示「风险 写入」（`80`、`88` 两张截图都能看到），用户会以为 Bot 要写文件，实际只是想读。

**归属**：@架构。**建议**：把 `:455-460` 换成与 `:491-518` 同一套判断（抽成一个 `fn tool_risk(tool: &str) -> &'static str`，两处共用），`read` 的越界卡就会显示「风险 读取」。UI 侧标签映射齐全（`main.rs:6567-6572` 有 exec/执行、write/写入、read/读取），不需要改。

**影响**：群协作时**每一次文件读都被要求确认**，卡上还写着「越界访问…归属 自己」，用户会当成 bug；判错方向是「多问一次」（fail-closed），所以不构成泄漏。但群聊里工具基本不可用，且会让人怀疑隐私守卫本身是否可靠。

**同一根因的第二个症状（代码推导，本轮未单独实机验证）**：`backend.rs:1108` 用同一个 `run_bot_id` 决定是否注入记忆工具（`memory_tools::tools(None)` 返回空表）。群成员 identity 解析不出 bot_id，所以**群里的 Bot 没有 `remember` / `recall` 工具**；bot 记忆的 system prompt 注入（`rpi_engine.rs:366`）同样被跳过。是否要在群聊里支持 Bot 记忆，需要产品口径；至少「静默降级」这一点要说明。

**归属**：@架构（`rpi_engine.rs` 的 identity 解析）。
**建议修法**：`bot_id_from_identity` 增加一种形态 —— `mode-bot:group:<gid>:member:<id>` 取末段 `<id>`；或让 `AskPermission` 显式带上成员 id 而不是从 identity 反解。顺带补一个单测：群成员 identity 必须解析出 bot_id。
