# Mode Chat v0.6.0 发布说明

**主题：只保留微信风外壳，并在它上面做一轮界面与交互优化。**

这一版最大的变化不是加功能，是**删掉一整套外壳**：DS Bot 风格的 classic 三栏外壳（`src/main.rs` 约 3013 行 + `theme.rs` 约 20 行）整段删除，仓库里只剩微信风一套。**没有留可回退开关**——这不是配置项，是代码真的没了。

删除之后，原本只在 classic 上存在、用户能看见的能力被搬回微信壳，并顺带修掉几处「点了没反应」的交互缺陷。下面是用户能直接感知的部分。

## 用户能看见的变化

| # | 变化 | 之前 | 现在 |
| --- | --- | --- | --- |
| O-1 | **空会话欢迎区 + 三条建议 chip**（单聊 / 群聊两条路径都有） | 空会话只有一片空白，不知道能做什么 | 头像 + 欢迎语 + 三条可点的建议；点 chip 直接填进输入框并聚焦。群聊侧是九宫格头像 + 「群名 · N 人」+ 成员名单 |
| O-2 | **「⋯ → 运行状态」不再是死按钮** | 点了设了状态但没有任何渲染点，用户看不到反应 | 右栏基础卡出微信绿描边 + 一行「运行状态」标题；**待处理三项为 0 时也照样画出来**（0 本身是「没有在等你处理」这条信息）。关右栏、切 Bot、切群、切历史会话、点改名——五个入口都会清掉高亮，不会跨会话残留 |
| O-3 | **工作状态行按工具分档** | 只有「工作中」/「重试中」两档，进度看不出在干什么 | 正在执行命令 / 正在改文件 / 正在检索 / 正在读文件 / 正在操作界面；取本轮**最后一条**工具消息分类。重试仍优先于任何工具状态。未知工具回落「工作中」 |
| O-4 | **秒数对齐整秒跳** | 固定睡 1000ms 累加，调度延迟会让秒数忽快忽慢 | 按「距下一个整秒还有多久」睡眠，跳变时刻对齐墙钟 |
| O-6 | **长 Bot 名不再把右侧按钮挤出屏幕** | `flex_1` + `truncate()` 缺 `min_w(px(0.))`，长名字会把「就绪」badge 和折叠按钮顶出右栏 | 名字末尾省略号，按钮留在原位，右栏总宽不变 |
| O-7 | **禁用按钮真的禁用** | 只改颜色，光标还是手形、hover 还有高亮、点了还会响应 | `button_state` / `button_ghost_state` **分支构造**：禁用分支里根本不存在 `cursor_pointer()` 和 `hover()`，不是事后覆盖 |
| D3 | **会话可以改名** | classic 的「改名」随 sidebar 删掉了，微信壳没有入口 | 右栏「最近会话」每行末尾一个「改名」，点开预填当前名字，留空保存 = 恢复默认短名 |

### D3 有一个必须知道的设计边界

**当前正在用的会话改不了名。** 改名入口只挂在「最近会话」那几行上，而当前会话被 `filter(|id| live != id)` 排除在外。**要先切到别的 Bot / 会话，它才会出现在「最近会话」里。** 这不是缺陷，是结构决定的；按「打开一个会话就地改名」写的用例一定会失败，失败原因不在改名功能。

## 已知问题（都写进来，不等用户自己发现）

### 1. O-3 / O-4 的运行期截图缺失，原因是模型计费层阻断

```
现象   Agent 一发起工具调用就被 402 拦下，billing_error / Insufficient Balance
证据   docs/testing/shots/269-o3-blocked-billing.png、docs/testing/shots/272-tokendance-402.png
       两个 provider、三个不同 request_id，全部 billing_error
后果   O-3 的状态行分档、O-4 的秒数跳变都拿不到「真的跑起来了」的可证伪帧
记法   代码已入库、运行期截图待补
```

**不得写成「已验证」或「链路跑通」。** 代码层（`working_phrase` 六档映射 + 五条 `i18n` 英文译文 + `filter(|name| !name.is_empty())`）是完整的，但没有一张同帧能同时看到状态行短语和工具卡工具名。

### 2. 「折叠清空运行状态高亮」的证据是跨批次的

```
点亮态   264-4b-1-lit    exactGreen=2248                       已留证
折叠     266-4b-2        panel=ABSENT  exactGreen=0            已实拍
展开后清 266-4b-3        panel=present exactGreen=0            已实拍 ← 这条是核
```

`264` 整组作废（同组第 3 帧名字写 `reopened`，探针实测 `panel=ABSENT`，拍的是折叠态）。**点亮态那张是单独留证的，不能并进 `266` 的两帧拼成三连。**

**记法：「代码已确认 + 核心帧已拍」**——不写「完整三连通过」（那会把跨批次拼成一条链），也不写「未做运行期验证」（那会把已拍到的核心帧抹掉）。

### 3. 232 处非 4px 档间距未逐处清理

```
-EnforceSpacing 实测 232 处档外间距
  px(6.) 82 / px(10.) 52 / px(2.) 45 / px(14.) 29 / px(5.) 7
  px(1.) 6 / px(9.) 5 / px(3.) 3 / px(7.) 3
```

**这是看得见的粗糙感**（图标间距、行距不齐），但 `px(6)` 改成 4 还是 8 **取决于位置**——两个图标之间改 4 会太紧、改 8 会太松，是四天的视觉走查，不是四天的替换。

**本版只做到「规则存在 + 基线已报」，清零单独立项**（PRD O-5 ③）。跑 `-EnforceSpacing` 会红，这是事实，不代表本版没通过门禁——六道门禁用的是 `-Enforce`，它只管前四条规则。

### 4. 引用条未做

`chat.quote` 字段全仓 **0 个写入点**：有声明、有初始化 `None`、有四处 `take()` 消费、有拼接函数和单测，唯独没有任何一处写 `Some(...)`。**只加渲染等于加一个永远为空的控件。**

v0.7 三件事一起做：写入点（气泡动作条上加「引用」）+ 渲染点（composer 上方 28px 条）+ **五处清空点**（与 `chat_detail` 同位置）。界面上现在没有「引用」按钮，所以不存在「点了没反应」——**别写成「点击无反应」，那会让人以为有坏按钮**。

---


### 5. 随附探针的一个已知局限（不影响本版读数）

`scripts/shot-probe.ps1` 在统计 `exactGreen` 时只限定了 x 区间（`x >= 0.72W`），**没有限定 y 区间**。后果：输入框有字时，composer 右下角「发送」按钮是精确 `0x07C160`，它落在右栏的 x 区间内，会被算成「右栏高亮」——实测踩到过一次，读数 `1182`。

本版 4b / 4c 的证据帧输入框都是空的（发送按钮是灰的），所以 `2248 / 0 / 0` 三个读数不受影响。但**用这个 tag 复核、且输入框里有字时，必须手工排除底部约 147px**。

修复（`exactGreen` 的 y 范围收到与定位右栏同一区间）已在工作区完成，随 v0.6.1 提交。

## 从 v0.5.1 升级

- **数据目录不变**：仍读 `~/.mode-bot`，无需迁移。classic 删除不涉及任何持久化结构。
- **没有回退开关**：`BOT_PILOT_CLASSIC_UI` 环境变量已随 classic 删除失效，设了也不会回到三栏外壳。
- **首次启动**：窗口宽度与右栏开合沿用 `ui-prefs`；右栏开合会联动窗口宽度（展开无条件 +320，收起还原——`panel_restore_width` 为 `None` 时不缩，这解释了同一操作序列里尺寸会变，不是换实例）。
